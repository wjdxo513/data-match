목적

나는 사내에서 사용할 DB 거래 데이터 비교 자동화 프로그램을 개발하려고 해. 개발에 앞서 PRD(Product Requirements Document, 제품 요구사항 정의서)를 작성하고 싶어. 너는 나와 대화하면서 요구사항을 구체화하고, 최종적으로 실제 개발에 활용할 수 있는 PRD를 완성해야 해.

프로젝트 개요

프로젝트명(가칭): DB 거래 데이터 비교 자동화 시스템

현재 회사에서는 동일한 데이터베이스에 저장된 서로 다른 거래 데이터를 비교하는 업무가 자주 발생해. 사내에는 비교할 테스트케이스가 여러개 있고 각 테스트케이스에는 거래번호가 있어 이 거래번호가 key값이야. 이 테스트케이의 거래번호를 같은 DB에서 조회해서 각 컬럼값을 비교하는 거야.

기존에는 담당자가 SQL을 직접 작성하여 거래 데이터를 조회하고, 결과를 수작업으로 비교해야 하기 때문에 반복적인 작업이 많아. 이러한 과정을 자동화하여 개발자나 운영 담당자가 SQL을 직접 작성하지 않고도 거래 데이터를 손쉽게 비교할 수 있는 프로그램을 만들고 싶어.

현재 구상 중인 주요 기능

① DB 연결

데이터베이스에 연결할 수 있어야 해. DB 연결 정보를 설정하고 관리할 수 있어야 해. 초기에는 동일한 DB 내 데이터 비교를 지원할 예정이야.

② 비교 대상 선택

사용자가 비교할 테이블을 선택할 수 있어야 해. 테이블을 검색할 수 있는 기능과 자동완성 기능을 제공했으면 좋겠어. 각 테이블의 컬럼 정보를 확인할 수 있어야 해. 비교할 컬럼을 여러개 선택할 수 있어야 해. 비교할 컬럼은 체크박스 형태로 지원할 수 있으면 좋겠어.

③ 데이터 비교

여러 개의 거래 데이터를 순서대로 비교할 수 있어야 해. 거래번호, 금액, 승인전문, 유저 입력값 등 여러 컬럼을 비교할 수 있어야 해. 일치, 불일치, 데이터 누락 등을 구분할 수 있어야 해. safe dB로 암호화된 데이터는 복호화 후 데이터 비교할 수 있는 기능이 필요해.

④ 비교 결과

비교 결과를 화면에서 확인할 수 있어야 해. 어떤 컬럼에서 어떤 데이터의 차이가 발생했는지 확인할 수 있어야 해. 비교 결과를 엑셀로 다운로드할 수 있는 기능도 있으면 좋겠어.

위 기능은 확정된 요구사항이 아니라 현재 구상 단계의 아이디어야. 더 좋은 방법이 있다면 제안해 줘.

PRD 작성 방식

다음 규칙을 반드시 지켜 줘.

처음부터 완성된 PRD를 작성하지 마. 먼저 프로젝트를 이해하고 필요한 요구사항을 분석해 줘. 요구사항이 불명확하거나 빠져 있다면 나에게 질문해 줘. 질문은 한 번에 3~5개 정도로 제한하고, 답변을 바탕으로 다음 질문을 이어가 줘. 내가 결정하지 않은 사항은 임의로 확정하지 마.

기능을 무조건 추가하지 말고 실제 업무에 필요한 기능인지 검토해 줘. 복잡한 기능보다는 사용하기 쉽고 유지보수가 편리한 구조를 우선해 줘. 모든 요구사항을 필수 기능(MVP)과 추후 확장 기능으로 구분해 줘.

내가 답변한 내용은 다음 단계에 계속 반영해 줘. 요구사항이 충분히 정리되면 PRD 초안을 제시하고 내 검토를 받아 최종 문서를 완성해 줘.

최종 PRD 구성

PRD는 아래 목차로 작성해 줘.

프로젝트 개요
개발 배경 및 문제점
프로젝트 목표
주요 사용자 및 사용 시나리오
핵심 기능 요구사항
데이터 비교 규칙 및 처리 방식
비기능 요구사항 (성능, 보안 등)
MVP 개발 범위
추후 확장 기능
미결정 사항

기능 요구사항에는 기능 ID, 기능명, 상세 설명, 우선순위를 표로 정리해 줘.

주의사항

PRD는 개발자가 실제로 참고할 수 있을 만큼 구체적으로 작성해 줘. 다만 화면 상세 설계, ERD, API 명세 등은 별도 문서로 작성할 예정이므로 PRD에 지나치게 포함하지 마. 불필요하게 문서 분량을 늘리지 마. 일반적인 설명보다 실제 업무에 필요한 내용을 우선해 줘.

PG 거래 데이터를 다루는 사내 프로그램이므로 운영 DB에 대한 읽기 전용 접근, 민감정보 보호, 조회 성능도 고려해 줘. 확정된 요구사항과 제안사항을 명확히 구분해 줘.

이제 프로젝트 개요를 검토하고, PRD 작성을 위해 가장 먼저 결정해야 할 핵심 질문 3~5개부터 시작해 줘.
