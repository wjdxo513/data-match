## 1. 문서 개요

- 목적: 사용자가 어떤 순서로 프로그램을 쓰고 시스템이 어떻게 반응해야 하는지 정의한다. 화면 정의서 작성의 기초 자료다.
- 범위: PRD의 MVP 필수 기능(FR-01~FR-09). FR-10, FR-11, EX-01~04는 포함하지 않는다.
- 구현 코드, API, DB 설계는 다루지 않는다.

## 4. 정상 사용자 시나리오

### SN-01. 동일 환경 거래 비교

- **목적**: SQL 없이 같은 환경 DB의 두 거래를 선택한 컬럼 기준으로 비교한다.
- **사용자**: 개발자, 운영 담당자
- **사전 조건**: DataMatch가 담당자 PC에서 실행 중이다. 개발·테스트·운영 접속 정보(properties)가 준비되어 있고 해당 DB에 접근할 수 있다(PA-08).
- **시작 조건**: 사용자가 비교할 거래번호 짝(A, B)과 비교할 테이블·컬럼을 알고 있다.
- **정상 흐름**

| 단계 | 사용자 행동                                              | 시스템 반응                                                                                         | 요구사항 |
| ---- | -------------------------------------------------------- | --------------------------------------------------------------------------------------------------- | -------- |
| 1    | A쪽 환경과 B쪽 환경을 같은 환경(예: 테스트)으로 선택한다 | 선택한 환경을 화면에 표시한다. 운영이 포함되면 눈에 띄게 표시한다(NFR-07)                     | FR-01    |
| 2    | 테이블 이름 일부를 입력해 검색한다                       | 입력에 맞는 `스키마.테이블` 후보를 자동완성으로 보여주고, 후보가 30건을 넘으면 일부만 표시하며 검색어를 더 입력하도록 안내한다. PK가 없거나 복합 PK이거나 지원하지 않는 PK 타입인 테이블은 선택 불가와 사유를 표시한다 | FR-02    |
| 3    | 테이블을 선택한다                                        | 컬럼명과 타입 목록을 보여주고 PK 컬럼을 키로 인식했음을 표시한다                                    | FR-02, 03 |
| 4    | 비교할 컬럼을 체크박스로 선택한다(컬럼 이름 검색, 전체 선택/해제 사용 가능)                        | 선택한 컬럼을 표시한다. 선택하지 않은 컬럼은 비교 대상이 아니다                                     | FR-03    |
| 5    | (암호화 컬럼이 있으면 SN-03 수행)                        | -                                                                                                   | FR-04    |
| 6    | `거래번호A,거래번호B`를 한 줄씩 붙여넣거나 입력한다      | 입력 형식을 검사한다(오류 처리는 SN-E03)                                                            | FR-05    |
| 7    | 비교를 실행한다                                          | 비교를 시작하고 진행률(처리 건수/전체 건수)과 중지 버튼을 표시한다                                  | FR-06    |
| 8    | 비교 완료를 기다린다                                     | 짝별 `A1-B1: 일치/불일치/누락` 요약 목록을 보여준다. 불일치는 빨간색으로 표시한다                   | FR-08    |
| 9    | 확인할 짝을 선택한다                                     | 상세 화면을 보여준다(SN-04)                                                                         | FR-08    |

- **예외 흐름**: SN-E01~SN-E04
- **완료 조건**: 모든 짝에 일치/불일치/누락 중 하나의 판정이 표시되고, 사용자가 불일치 짝의 차이를 확인할 수 있다.
- **관련 요구사항**: FR-01~FR-08

### SN-02. 테스트·운영 환경 간 거래 비교

- **목적**: 테스트 DB의 거래와 운영 DB의 거래를 비교한다. 환경마다 거래번호가 다르다.
- **사용자**: 개발자
- **사전 조건**: SN-01과 같다. 두 환경의 테이블·컬럼 구조는 동일하다(PA-15). 두 환경의 SafeDB 인증 설정은 같다(PA-14).
- **시작 조건**: 사용자가 테스트 거래번호와 그에 대응하는 운영 거래번호를 알고 있다.
- **정상 흐름**: SN-01과 같으며 아래 단계만 다르다.

| 단계 | 사용자 행동                                       | 시스템 반응                                                                                                  | 요구사항 |
| ---- | ------------------------------------------------- | ------------------------------------------------------------------------------------------------------------ | -------- |
| 1    | A쪽 환경을 테스트, B쪽 환경을 운영으로 선택한다   | 두 환경을 각각 표시한다. 운영 환경은 눈에 띄게 표시한다(NFR-07)                                        | FR-01    |
| 3    | 테이블을 선택한다                                 | 두 환경의 구조가 같으므로 테이블·컬럼 정보는 A쪽 환경 기준으로 보여준다                                      | FR-02, 03 |
| 6    | A 거래번호(테스트), B 거래번호(운영)를 한 줄에 입력한다 | 거래번호A는 A쪽 DB에서, 거래번호B는 B쪽 DB에서 조회하도록 짝을 맺는다                                        | FR-05    |
| 8    | 결과를 확인한다                                   | 요약·상세의 A값·B값 머리글에 환경(예: A=테스트, B=운영)을 표시한다                                           | FR-06, 08 |

- **예외 흐름**: SN-01과 같다. 한쪽 환경만 연결에 실패해도 전체 비교는 실패로 처리한다(SN-E01).
- **완료 조건**: 각 짝이 서로 다른 환경의 거래로 비교되어 판정과 환경이 함께 표시된다.
- **관련 요구사항**: FR-01, FR-05, FR-06, FR-08

### SN-03. SafeDB 암호화 컬럼 복호화 후 JSON 필드별 비교

- **목적**: 암호화된 CLOB 컬럼(승인전문 등)을 복호화해 JSON 필드 단위로 비교한다.
- **사용자**: 개발자, 운영 담당자
- **사전 조건**: SafeDB 인증 설정이 PC에 배치되어 있다(NFR-05). 사용자 권한 구분은 없다.
- **시작 조건**: SN-01의 4단계에서 비교 컬럼 중 암호화된 CLOB 컬럼이 있다.
- **정상 흐름**

| 단계 | 사용자 행동                                          | 시스템 반응                                                                                           | 요구사항 |
| ---- | ---------------------------------------------------- | ----------------------------------------------------------------------------------------------------- | -------- |
| 1    | 선택한 CLOB 컬럼을 "SafeDB 복호화 대상"으로 지정한다 | 해당 컬럼을 복호화 대상으로 표시하고 정책을 KDKEY(기본)로 보여준다                                    | FR-04    |
| 2    | 필요하면 컬럼별 정책을 PANEN으로 바꾼다              | 변경된 정책을 표시한다                                                                                | FR-04    |
| 3    | SN-01 6~7단계로 비교를 실행한다                      | 값이 있는 행만 복호화한 뒤 JSON 필드로 펼쳐 비교한다. 양쪽 모두 NULL이면 일치로 본다                   | FR-07    |
| 4    | 요약 목록에서 짝을 선택한다                          | 복호화 컬럼은 필드별 A값·B값을 나란히 보여주고 불일치 필드를 빨간색으로 표시한다. 한쪽에만 있는 키는 없는 쪽을 NULL로 보여준다 | FR-07, 08 |

- **예외 흐름**: 복호화 실패, JSON 해석 실패는 SN-E04
- **완료 조건**: 복호화 컬럼의 필드별 비교 결과가 화면에 표시된다.
- **관련 요구사항**: FR-04, FR-07, FR-08

### SN-04. 비교 결과 상세 확인 및 엑셀 다운로드

- **목적**: 어떤 컬럼·필드에서 어떤 차이가 났는지 확인하고, 결과를 엑셀로 남긴다.
- **사용자**: 개발자, 운영 담당자
- **사전 조건**: 비교가 완료되어 요약 목록이 표시되어 있다.
- **시작 조건**: 사용자가 결과를 검토하려 한다.
- **정상 흐름**

| 단계 | 사용자 행동                          | 시스템 반응                                                                                                             | 요구사항 |
| ---- | ------------------------------------ | ----------------------------------------------------------------------------------------------------------------------- | -------- |
| 1    | 요약 목록에서 불일치 짝을 선택한다   | 컬럼(복호화 컬럼은 필드)별 A값과 B값을 나란히 보여준다. 불일치·오류 항목은 빨간색, 일치 항목은 일반 표시                | FR-08    |
| 2    | 누락 짝을 선택한다                   | 어느 쪽 거래가 없는지 표시한다. 컬럼 비교는 하지 않는다                                                                 | FR-08    |
| 3    | 엑셀 다운로드를 요청한다             | 요약과 상세를 엑셀로 내려받게 한다. 화면과 같은 빨간색 강조를 적용하고 A쪽·B쪽 환경을 함께 기록한다                      | FR-09    |

- **예외 흐름**: 엑셀 다운로드 실패는 SN-E04
- **완료 조건**: 사용자가 차이를 확인했고 엑셀 파일을 저장했다.
- **관련 요구사항**: FR-08, FR-09

## 5. 예외 사용자 시나리오

### SN-E01. 연결·조회 오류와 비교 중단

| ID       | 상황                                   | 시점                          | 시스템 처리                                                                 | 상태                        |
| -------- | -------------------------------------- | ----------------------------- | --------------------------------------------------------------------------- | --------------------------- |
| SN-E01-1 | DB 연결 실패                           | 비교 실행 중                  | 전체 비교를 실패로 처리하고 안내한다. 부분 결과는 만들지 않는다(PA-17)      | 확정                        |
| SN-E01-2 | DB 연결 실패                           | 환경 선택·테이블 조회 단계    | 오류를 안내하고 다시 시도할 수 있게 한다                 | 확정 (SA-01)      |
| SN-E01-3 | 조회 가능한 테이블이 없음              | 테이블 검색                   | 빈 상태 안내(조회 가능한 테이블 없음)를 표시한다                 | 확정 (SA-02)      |
| SN-E01-4 | 조회 타임아웃(30초)                    | 비교 실행 중                  | 전체 비교를 실패로 처리하고 안내한다. 부분 결과는 만들지 않는다(PA-17)      | 확정                        |
| SN-E01-5 | 사용자가 비교 중지 버튼을 누름         | 비교 실행 중                  | 비교를 취소하고 결과를 만들지 않는다. 입력값은 유지되어 다시 실행할 수 있다 | 확정 (PA-18, SA-07)         |
| SN-E01-6 | 서버(프로그램)와 통신할 수 없음        | 모든 단계                     | 현재 영역에 안내하고 입력값을 유지한다                                      | 확정 (SA-10)                |
| SN-E01-7 | 이전 비교가 서버에서 아직 진행 중(예: 비교 중 새로고침) | 비교 실행 | 새 비교를 시작하지 않고 잠시 후 다시 시도하도록 안내한다 | 확정 (SA-11)                |

### SN-E02. 테이블·컬럼 선택 오류

| ID       | 상황                                      | 시점          | 시스템 처리                                                      | 상태                   |
| -------- | ----------------------------------------- | ------------- | ---------------------------------------------------------------- | ---------------------- |
| SN-E02-1 | PK가 없거나 복합 PK이거나 지원하지 않는 PK 타입인 테이블을 선택하려 함 | 테이블 선택   | 선택 불가로 표시하고 사유를 보여준다(PA-10, PA-19)                      | 확정                   |
| SN-E02-2 | 비교 컬럼을 하나도 선택하지 않고 실행     | 비교 실행     | 비교를 시작하지 않고 컬럼 선택을 안내한다  | 확정 (SA-03) |

### SN-E03. 거래번호 입력 오류

| ID       | 상황                                           | 시점      | 시스템 처리                                                                        | 상태                   |
| -------- | ---------------------------------------------- | --------- | ---------------------------------------------------------------------------------- | ---------------------- |
| SN-E03-1 | 형식 오류 줄이 있음(구분자 없음, 값 비어 있음, 구분자 2개 이상, 숫자 PK 테이블에 숫자가 아닌 값) | 비교 실행 | 오류 줄을 줄 번호와 함께 알리고, 비교를 시작하지 않고 수정을 요구한다(PA-17)       | 확정                   |
| SN-E03-2 | 입력 건수가 1,000쌍을 초과                     | 비교 실행 | 전체를 거절하고 안내한다(PA-17)                                                    | 확정                   |
| SN-E03-3 | 입력이 비어 있음(0건)                          | 비교 실행 | 비교를 시작하지 않고 입력을 안내한다                         | 확정 (SA-04) |

### SN-E04. 비교 중 개별 오류와 엑셀 다운로드 실패

| ID       | 상황                                | 시점          | 시스템 처리                                                                                         | 상태                   |
| -------- | ----------------------------------- | ------------- | --------------------------------------------------------------------------------------------------- | ---------------------- |
| SN-E04-1 | A 또는 B 거래 데이터가 존재하지 않음 | 비교 중       | 해당 짝을 "누락"으로 표시하고 어느 쪽이 없는지 보여준다. 나머지 짝은 계속 처리한다(FR-06)            | 확정                   |
| SN-E04-2 | A·B 거래가 모두 존재하지 않음       | 비교 중       | 누락으로 처리하고 "A·B 모두 없음"으로 표시한다              | 확정 (SA-05) |
| SN-E04-3 | SafeDB 복호화 실패                  | 비교 중       | 해당 컬럼만 "복호화 오류"를 빨간색으로 표시하고 나머지 컬럼은 계속 비교한다. 짝은 불일치로 집계하고 사유를 표시한다(PA-05) | 확정                   |
| SN-E04-4 | 복호화 결과 JSON 해석 실패          | 비교 중       | SN-E04-3과 같다                                                                                     | 확정                   |
| SN-E04-5 | 일부 거래 비교 중 오류              | 비교 중       | 짝 단위로 이어서 처리하는 오류는 누락, 복호화 오류뿐이다. 그 외 오류(연결 실패, 타임아웃)는 전체 비교 실패다(PA-17) | 확정                   |
| SN-E04-6 | 엑셀 다운로드 실패                  | 엑셀 다운로드 | 오류를 안내하고 화면 결과는 유지하며 다시 시도할 수 있게 한다                 | 확정 (SA-06) |

### 경계값

| 항목              | 값                       | 기대 동작                                |
| ----------------- | ------------------------ | ---------------------------------------- |
| 입력 짝 수        | 0건                      | 비교 시작 안 함, 입력 안내 (SA-04)                    |
| 입력 짝 수        | 1건, 1,000건             | 정상 처리 (NFR-01)                       |
| 입력 짝 수        | 1,001건                  | 전체 거절 (SN-E03-2)                     |
| 선택 컬럼 수      | 0개                      | 비교 시작 안 함, 컬럼 선택 안내 (SA-03)                    |
| 선택 컬럼 수      | 1개 이상                 | 정상 처리                                |
| 입력 줄 구분자    | 쉼표 또는 탭             | 정상. 구분자 없음, 구분자 2개 이상, 한쪽 값이 비어 있으면 오류 (SN-E03-1) |
| 숫자 PK 입력      | 숫자가 아닌 값           | 오류 줄 (SN-E03-1, PA-19)                |
| 조회 시간         | 30초 초과                | 전체 비교 실패 (SN-E01-4)                |
| 처리 시간 기대치  | 50쌍 10초, 500쌍 60초 이내 | 초기값, 실측 후 조정 (PA-03)            |

## 6. PRD 요구사항 매핑

| 요구사항 | 내용                      | 시나리오                          |
| -------- | ------------------------- | --------------------------------- |
| FR-01    | 환경별 DB 연결            | SN-01, SN-02, SN-E01              |
| FR-02    | 테이블 검색·선택          | SN-01, SN-02, SN-E01, SN-E02      |
| FR-03    | 컬럼 조회·선택            | SN-01, SN-02, SN-E02              |
| FR-04    | 복호화 컬럼 지정          | SN-03                             |
| FR-05    | 거래번호 짝 입력          | SN-01, SN-02, SN-E03              |
| FR-06    | 비교 실행·진행 표시       | SN-01, SN-02, SN-E01, SN-E04      |
| FR-07    | 복호화 및 JSON 필드 비교  | SN-03, SN-E04                     |
| FR-08    | 결과 요약·상세 화면       | SN-01, SN-02, SN-03, SN-04        |
| FR-09    | 엑셀 다운로드             | SN-04, SN-E04                     |

NFR 중 사용자 화면에 드러나는 것은 NFR-07(운영 환경 경고, SN-01·02)과 NFR-01·02(건수 상한, 타임아웃, SN-E01·E03)이다. 나머지 NFR은 화면 시나리오 대상이 아니다.

## 7. 추가 확인 사항

PRD에 규칙이 없던 상황은 모두 제안대로 확정했다. SA-10, SA-11은 최종 검토에서 추가했다.

| ID    | 구분 | 내용                                                                                                                              |
| ----- | ---- | --------------------------------------------------------------------------------------------------------------------------------- |
| SA-01 | 확정 | 환경 선택·테이블 조회 단계의 DB 연결 실패는 오류를 안내하고 다시 시도할 수 있게 한다                                               |
| SA-02 | 확정 | 조회 가능한 테이블이 없으면 빈 상태 안내를 표시한다                                                                                |
| SA-03 | 확정 | 비교 컬럼을 하나도 선택하지 않으면 비교를 시작하지 않고 안내한다                                                                   |
| SA-04 | 확정 | 거래번호 입력이 비어 있으면 비교를 시작하지 않고 안내한다                                                                          |
| SA-05 | 확정 | A·B 거래가 모두 없는 짝은 누락으로 처리하고 "A·B 모두 없음"으로 표시한다                                                           |
| SA-06 | 확정 | 엑셀 다운로드에 실패하면 오류를 안내하고 화면 결과는 유지하며 다시 시도할 수 있게 한다                                              |
| SA-07 | 확정 | 비교 중지 후 입력값(환경·테이블·컬럼·거래번호)은 유지된다                                                                          |
| SA-08 | 확정 | 새 비교를 실행하면 이전 결과는 새 결과로 대체한다                                                                                  |
| SA-09 | 확정 | 입력값 유지 정책: 같은 페이지에서는 입력값을 유지하고, 브라우저를 새로고침하거나 다시 열면 초기화한다. 설정을 바꿔도 이전 결과는 다음 비교 실행 전까지 유지하며, 결과에는 비교 당시 조건(환경·테이블)을 함께 표시한다 |
| SA-10 | 확정 | 서버(프로그램)와 통신할 수 없으면 발생한 영역에 안내하고 입력값을 유지한다 |
| SA-11 | 확정 | 비교 중 새로고침 등으로 서버에 이전 비교가 남아 있으면 새 비교를 시작하지 않고 잠시 후 다시 시도하도록 안내한다. 이전 비교는 서버에서 끝까지 실행된 뒤 다음 비교 때 폐기된다(SA-08) |
